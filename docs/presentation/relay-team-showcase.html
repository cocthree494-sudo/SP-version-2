Why this exists

Support teams have knowledge. Customers still wait for answers—or receive guesses.

01

Knowledge is fragmented

Policies live across files, sites, and tribal knowledge. Finding the right answer is slower than answering it.

02

Generic AI is risky

Without retrieval boundaries, citations, and safe fallback, fluent responses can become expensive hallucinations.

03

SaaS trust is structural

Tenant data, provider secrets, jobs, vectors, and logs must be isolated from day one—not patched later.

Our goal: grounded, multilingual answers at low cost, with graceful failure and evidence.

Product boundary

Built around three actors—and a deliberately focused MVP.

C

End customer

Asks in any supported language, receives a streamed answer, sees citations where the channel supports them, and gets a safe fallback when evidence is weak.

Outcome: faster, trustworthy self-service.
T

Tenant team

Creates bots, adds knowledge, watches ingestion, tests answers, configures the widget, controls provider routing, and monitors usage.

Outcome: control without infrastructure burden.
P

Platform operator

Runs migrations, health checks, workers, backups, recovery, CI, cost and latency telemetry. Full platform-admin UI is intentionally deferred.

Outcome: observable, reversible operations.

Security architecture

Tenant isolation is a layered invariant—not one WHERE clause.

1 · Request boundary

Resolve authenticated tenant, bot, role, and origin once; reject conflicts early.

IDENTITY
2 · Domain/repository

Every tenant-owned query carries explicit `tenant_id` predicates and ownership checks.

APPLICATION
3 · PostgreSQL RLS

Transaction-local tenant context + forced policies under a non-superuser runtime role.

DATABASE
4 · Async boundaries

Queue payloads, rate-limit keys, storage paths, retrieval filters, and logs include tenant scope.

INFRA
5 · Release proof

Cross-tenant reads/writes, pgvector retrieval, append-only usage, credentials, and policies are tested live.

Key decisions

What we optimized for—and what we intentionally postponed.

Multi-tenant from day oneExplicit scope + RLS everywhereMore upfront rigor; avoids unsafe retrofitting.
Channel-neutral coreWeb widget first; thin future adaptersShip one channel without coupling the agent to it.
PostgreSQL + pgvectorRelational + vector + lexical in one systemOperational simplicity before specialized search scale.
Async ingestionRedis-backed workerReliable long work; eventual readiness instead of request blocking.
Grounding before fluencyCitation validation + safe fallbackRefusal is better than an unsupported answer.
Platform default + optional BYOKExplicit routing modesEasy onboarding and customer control without silent cost transfer.
Docker / config boundariesHosting and model IDs remain replaceableVendor choices are still open; keep decisions reversible.
